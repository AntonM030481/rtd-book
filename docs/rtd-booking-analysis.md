# RTD: запись на экзамен и возможности автоматизации

Проверено 17 ноября 2026 года, часовой пояс Asia/Nicosia.

## Результат

Практически полезный первый этап — монитор свободных часов в авторизованном браузере с фильтрами и уведомлением. Автоматическое завершение бронирования пока не подтверждено: свободный слот, резервирование, платёж и финальное подтверждение в этом исследовании не проходились.

Исследование выполнено на живом интерфейсе открытой пользователем вкладки. Учётная запись уже была авторизована. Пароли, cookies и персональные идентификаторы не извлекались и в отчёт не сохранялись. Реальные записи, отмены и платежи не выполнялись. Рабочая папка на начало исследования не содержала исходного кода приложения.

Официальные объявления и ограничения собраны отдельно: [rtd-official-sources.md](rtd-official-sources.md).

## Наблюдаемый процесс

1. Авторизованный пользователь открывает `Driver's License Exam`.
2. Меню предоставляет пять разных операций:

| Название в интерфейсе | Назначение | Параметр `comingfrom` |
|---|---|---|
| Κράτηση και Πληρωμή για Εξέταση Άδειας Οδήγησης | Запись и оплата экзамена | 1 |
| Ακύρωση Εξέτασης Άδειας Οδήγησης | Отмена экзамена | 2 |
| Επανακράτηση Εξέτασης Άδειας Οδήγησης | Повторная запись | 3 |
| Αλλαγή Ημερομηνίας Εξέτασης Άδειας Οδήγησης | Изменение даты | 7 |
| Επανεκτύπωση Επιστολής Εξέτασης | Повторная печать письма о записи | 5 |

3. В проверенной сессии переход по первой операции открыл `NewestCalendar.jsp`: выбор экзаменационного центра, категории прав, регистрационного номера автомобиля и кнопка `Επόμενο` («Далее»). Страница предупреждает о соответствии автомобиля категории экзамена. Это наблюдение конкретной сессии, а не доказательство одинакового начального процесса для всех пользователей.
4. Доступные центры: Деринья, Ларнака, Лимасол, Никосия, Пафос. В этой учётной записи список категорий содержал `ΒΒ`; полный список допустимых категорий для других пользователей не проверялся.
5. Уже открытый календарь `NewCalendar1.jsp` показывал Никосию, поле даты, месячный переключатель и недельную таблицу понедельник–суббота. В проверенной таблице 12 часов на день, всего 72 ячейки. Это размер показанной сетки, не количество мест или экзаменаторов.
6. Легенда: зелёный — доступные часы (€20); красный — недоступные; синий — часы вне обычного рабочего времени с дополнительной платой €34,17. Это суммы из интерфейса; окончательный расчёт оплаты не проверен.
7. После выбора свободного часа ожидаются дальнейшие шаги записи/оплаты, но их последовательность, удержание места и условия оплаты не установлены этим исследованием.

Источники интерфейса: [портал RTD](https://rtd.mcw.gov.cy/WebPhase1/gui/Common/LoginFrameGreek.jsp?lang=en), [меню экзаменов](https://rtd.mcw.gov.cy/WebPhase1/gui/Common/NavBarNext.jsp?lang=en&type=driverLicenseInd), [начало записи](https://rtd.mcw.gov.cy/WebPhase1/gui/dlcalendar/PersonalDataPage.jsp?lang=en&comingfrom=1). Ссылки требуют действующей сессии и не гарантируют самостоятельного открытия нужного шага.

## Технические наблюдения

- Это приложение на JSP с вложенными HTML `frame`, а не одностраничное приложение с наблюдаемым публичным JSON API. Отсутствие публичного API не доказано; API и сетевой протокол не исследовались полностью.
- Внешний адрес вкладки остаётся `LoginFrameGreek.jsp?lang=en` даже когда внутри уже открыт календарь. Определять состояние по URL верхней вкладки нельзя.
- Найденная структура: внешний `frame[src="TPRTDLogo.jsp?lang=en"]`, внутри него `frame[name="center"]` с рабочей формой и отдельный `frame[name="left"]` с меню. Атрибут `src` фрейма может сохранять старое значение после внутренней навигации.
- `lang=en` переводит не всё: меню и календарь записи во многом остаются греческими. Автоматизации нужны реальные подписи и стабильные имена полей.
- Форма параметров: `RegForm`, метод POST, action `NewCalendarDate.jsp?lang=en`. Поля: `h_centre`, `h_licence_category`, `h_vrm`; кнопка `submitBtn`. Значения центра в наблюдаемом DOM: Никосия `1`, Лимасол `2`, Ларнака `3`, Пафос `4`, Деринья `7`. Категория передаёт составное значение, поэтому подставлять выдуманное `B` нельзя.
- Календарь: форма `vrmSearch`, метод POST, action `../../ExaminerDateServlet`. В DOM есть поля границ диапазона, центра, категории и режима. Сам факт наличия action не доказывает безопасность прямого повторения запроса и не является спецификацией API.
- Ячейки недоступных часов в исследованных неделях имеют `background="/WebPhase1/images/drivercalendar/redtime.gif"` и дочерний `<h5>` с часом, без ссылки выбора. Таким образом, занятые часы можно распознавать по DOM без OCR. Разметка свободного и сверхурочного слота ещё не проверена.
- Клик по дню сначала меняет поле даты, а недельная таблица обновляется позднее. Наблюдался промежуточный кадр с новой датой и старой неделей; впоследствии новая неделя загрузилась. Нужно ждать совпадения заголовков таблицы с выбранным диапазоном. Это не установленный дефект сайта.
- Проверены недели 30.11–05.12 и 07.12–12.12.2026: все показанные часы недоступны. Это не означает, что весь декабрь занят: есть отдельный официальный график публикации слотов. Вкладка возвращена к исходной неделе и дате 04.12.2026.

| Перенос существующей записи | Отдельная операция есть | Условия переноса и судьба старой записи при ошибке |

## Предлагаемый первый вариант

Локальный браузерный монитор (например, Playwright) с отдельным профилем, ручным входом при необходимости и сохранением состояния только локально. Выбор технологии — предложение; работающий монитор в рамках этого исследования не создан.

Последовательность: проверить авторизацию → проверить центр/категорию → открыть нужную неделю → дождаться её заголовков → прочитать доступные часы → применить пользовательские фильтры → сообщить о новом результате. При потере сессии, неизвестной разметке или ошибке загрузки результат должен быть «проверка не выполнена», а не «мест нет».

Предлагаемые параметры: центр, категория, автомобиль, допустимый диапазон дат/времени, разрешение на доплату и канал уведомления. Интервал запросов сделать настраиваемым с увеличением паузы при ошибках; допустимая нагрузка и лимиты RTD не установлены. В момент официального выпуска слотов особенно важно, чтобы сессия и форма были заранее готовы.

Не следует автоматически повторять подтверждение после тайм-аута: сначала проверить результат предыдущей попытки. Для успешной записи нужен подтверждённый результат RTD (данные записи/письмо), а не только исчезновение слота или экран платёжного сервиса. При переносе не отменять старую запись предварительно без проверки предусмотренного сайтом процесса.

## Неизвестное и следующий проверяемый шаг

Не установлены время жизни сессии, наличие CAPTCHA на свежем входе, ограничения частоты запросов, схема защиты POST, механизм резервирования, точная последовательность платежа, детали отмены/переноса и формат подтверждения. Существующая авторизация не позволяет сделать вывод об отсутствии CAPTCHA или дополнительных проверок.

Следующий шаг для реализации — наблюдать появление свободного слота в разрешённом для пользователя центре, зафиксировать его DOM и пройти путь до первого действия, создающего резерв или обязательство. После этого можно оценить полную автоматизацию записи предметно. Исследование не запускало наблюдение по расписанию и не создавало напоминаний.
